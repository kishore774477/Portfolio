From Zero to Production: Building Enterprise-Grade RAG with Hybrid Search & Reranking

Why basic vector search fails on real internal company data — and how combining BM25 keyword matching, cross-encoder rerankers, and strict evaluation boosted our retrieval precision from 62% to 89.4%.

Almost every software team today starts their GenAI journey with the classic "Naive RAG" pattern: take a bunch of PDFs, split them into 500-token chunks with LangChain, embed them using an OpenAI embedding model, throw them into ChromaDB or FAISS, and feed the top 3 chunks to a model like GPT-4o.

In a demo with 3 clean documents, it looks like pure magic. But the moment you deploy this against 500 pages of HR policies, IT compliance guidelines, or complex financial audits, it falls apart. Users ask specific questions like:

The "Exact Match" Failure: "What is the maximum reimbursement limit under section 4.2(b) for flight code EK502?"

Dense vector embeddings calculate conceptual similarity. They know that "flight" is related to "travel" and "airplane", but they have no idea what "EK502" or "section 4.2(b)" strictly denotes. The vector search retrieves general travel paragraphs, misses the clause entirely, and the LLM confidently hallucinates an answer.

When building our Enterprise RAG Knowledge Assistant, solving this exact reliability gap was the primary engineering challenge. Here is how we engineered an architecture that delivers enterprise reliability.

The 3 Pillars of Production RAG

To make RAG resilient against messy corporate documents, we moved beyond single-path vector retrieval into a 3-stage pipeline:

  1. Parent-Document Chunking & Metadata Enrichment: Embed small chunks for high search granularity, but pass the larger surrounding parent section to the LLM so it never loses paragraph context.
  2. Hybrid Retrieval (Dense Vectors + BM25 Sparse Search): Combine semantic meaning with exact keyword, product code, and acronym matching via Reciprocal Rank Fusion (RRF).
  3. Cross-Encoder Reranking: Run the candidate chunks through a cross-encoder model to score query-document relevance jointly rather than independently.

Implementing Hybrid Search & Reranking in Python

Here is a production-tested implementation demonstrating how we combine BM25 and Dense Vector search, followed by reranking using a HuggingFace Cross-Encoder:

enterprise_rag_pipeline.py Python 3.11 
from langchain_community.retrievers import BM25Retriever
from langchain_community.vectorstores import Chroma
from langchain_openai import OpenAIEmbeddings
from sentence_transformers import CrossEncoder

class ProductionHybridRAG:
    def __init__(self, documents, embedding_model="text-embedding-3-small"):
        self.embeddings = OpenAIEmbeddings(model=embedding_model)
        
        # 1. Sparse BM25 retriever for exact terms, SKU/policy IDs
        self.bm25_retriever = BM25Retriever.from_documents(documents)
        self.bm25_retriever.k = 10

        # 2. Dense Vector store for conceptual search
        self.vector_store = Chroma.from_documents(
            documents, self.embeddings, collection_name="enterprise_docs"
        )
        self.dense_retriever = self.vector_store.as_retriever(search_kwargs={"k": 10})

        # 3. Cross-Encoder for joint query-document relevance scoring
        self.reranker = CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2")

    def retrieve_and_rerank(self, query: str, top_n: int = 4):
        # Fetch top candidate pools from both retrievers
        sparse_docs = self.bm25_retriever.invoke(query)
        dense_docs = self.dense_retriever.invoke(query)

        # Deduplicate candidates by document chunk ID / content
        candidate_pool = {doc.page_content: doc for doc in (sparse_docs + dense_docs)}.values()

        # Score pairs (query, chunk_text) using the cross-encoder
        pairs = [[query, doc.page_content] for doc in candidate_pool]
        scores = self.reranker.predict(pairs)

        # Rank candidates by reranker score
        scored_candidates = sorted(
            zip(candidate_pool, scores), key=lambda x: x[1], reverse=True
        )

        # Filter low confidence matches (Confidence thresholding)
        filtered_docs = [
            doc for doc, score in scored_candidates[:top_n] if score > 0.15
        ]

        return filtered_docs

The Secret Weapon: Strict Grounding Guardrails

Retrieving the right documents is only half the battle. If a user asks a question that is genuinely not contained within the company documentation, a naive prompt will cause the model to synthesize assumptions.

We enforced strict system prompt constraints:

grounding_guardrails.py Prompt Strictness 
SYSTEM_PROMPT = """You are an Enterprise Knowledge Assistant.
Answer the user's question ONLY using the factual context provided below.
Rules:
1. If the context does not explicitly contain sufficient information to answer the question, 
   state: "I cannot find this information in the authorized documentation."
2. Every factual assertion must cite its source document tag: [Source: {doc_id}].
3. Never assume, extrapolate, or use pre-trained external knowledge for company facts."""

How We Evaluated the System: The RAG Triad

You cannot improve what you do not measure. Instead of relying on manual testing, we evaluated our assistant using automated metrics:

  • Context Relevance: Did the retriever return only chunks relevant to the user's prompt? (Scored 92% after reranking).
  • Groundedness (Faithfulness): Did the LLM make claims that are mathematically supported by the retrieved context? (Reached 95%).
  • Answer Relevance: Did the generated answer directly address the user's inquiry? (Reached 91%).

5 Key Takeaways for Builders

1. Never rely on pure vector search alone. Always use hybrid search (BM25 + Dense) if your documents contain acronyms, IDs, or domain-specific jargon.
2. Cross-encoders are worth the latency. Adding a lightweight reranker takes ~35ms, but eliminates 70% of irrelevant context chunks.
3. Preserve parent context. Embed small chunks (e.g. 200 tokens) for crisp vector matching, but retrieve the larger enclosing section (800 tokens) for LLM synthesis.
4. Set confidence score cutoffs. If the reranker score is below threshold, immediately return a safe fallback message instead of letting the LLM guess.
5. Test continuously with automated evals. Build an evaluation test suite with 50 golden question-answer pairs before pushing updates to production.
